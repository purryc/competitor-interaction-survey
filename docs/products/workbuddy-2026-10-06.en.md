Verified on: 2026-10-06. This study covers Tencent WorkBuddy, primarily the personal edition, with enterprise features identified separately. It is neither a renamed CodeBuddy IDE/CLI nor a study limited to voice input. The method cross-checks public official documentation, vendor support pages, named journalists' hands-on reports, original forum posts, and video pages. No installation or hands-on testing was performed, and no user device was accessed. The latest entry in the official changelog is **5.7.6 / 2026-10-04**.[S01](https://www.workbuddy.cn/docs/workbuddy/Changelog)

## 1. The Product at a Glance

WorkBuddy is an AI workbench that brings together natural-language tasks, executable tools, local/cloud workspaces, editable deliverables, specialist roles, shared team knowledge, and cross-device entry points. Its core extends beyond “answering questions” or “operating a computer”: it productizes the chain of **assign a task → obtain context → plan/call tools → generate or modify files → human review → save, share, hand off, or rerun on a schedule**. The home screen covers everyday office work, coding, and creative design; projects, libraries, connectors, experts/expert teams, and skills let work accumulate over time.[S02](https://www.workbuddy.cn/docs/workbuddy/)

### Product Map

| Layer | Specific objects in the product | What they do for the user | Boundaries not to confuse |
|---|---|---|---|
| Entry points | Windows/macOS clients, Web, mobile app, mini program, WeChat/WeCom/QQ/DingTalk/Feishu assistants, hardware | Assign tasks, supply material, approve, stop, and check results | A mobile entry point does not mean the task necessarily runs in the cloud |
| Execution | Local tasks, cloud tasks; files/scripts/connectors/browser/Computer Use | Actually read and write data, execute operations, and produce deliverables | Local execution does not mean local offline inference |
| Organization | Tasks, workspaces, projects, assistants | Separate ad hoc work, persistent folders, team collaboration, and remote conversation threads | Ordinary tasks can run in parallel; older local-assistant documentation describes a centralized single conversation |
| Context | Current files, library, project instructions, personal memory, references, connector data | Avoid repeatedly moving material and restating requirements | The library, personal memory, and system file permissions each have their own boundaries |
| Extensions | Skills, experts, expert teams, connectors, Buddy apps | Package tools, methods, and industry use cases for reuse | An expert is a role/method; it does not automatically confer additional permissions |
| Delivery | Word/Excel/PPT/PDF/MD/CSV, images/video, websites, and mini programs | Inspect results directly and continue editing | Preview support does not mean in-place integration with every external Office app |
| Continued use | Scheduled tasks, project handoffs, cloud deliverables, personal memory | Move from one-off Q&A to recurring work | Scheduled local tasks require an online machine; cross-device synchronization is not unrestricted synchronization of all data |

**Research assessment:** The competitive unit is the entire “workbench + workflow + Chinese office ecosystem + local/cloud execution” system. A screenshot of a chat box cannot capture it. At the same time, the official promise of being “everywhere” is an ecosystem vision; purchasable hardware, a live integration, and a launch-event demonstration must be treated as three distinct states.

### Interaction Is More Than a One-Time Submission

Current task conversations support additional instructions, references to output text/tables/components, process inspection, and a browser on the right. New messages sent during execution enter a queue and can be edited, deleted, or reordered; sending one immediately does not necessarily interrupt the current tool. Deliverables can be inspected in the file tree and changes view, then uploaded to cloud storage, Tencent Docs, or ima/Lexiang. Tasks can be searched, archived, and pinned. Global search across the library and chat history was added in late September.[S01](https://www.workbuddy.cn/docs/workbuddy/Changelog), [S07](https://www.workbuddy.cn/docs/workbuddy/Conversation), [S08](https://www.workbuddy.cn/docs/workbuddy/Results)

### Complete Chains That Explain “Why Use It?”

1. **A journalist writing an article**: Newly written Word document → open on the workbench's right side → select an achievements paragraph and convert it to a table → leave revision comments on the relevant paragraph → ask the agent to execute → inspect the original text. The value is reduced shuttling between chat and document, rather than merely generating another answer. Evidence comes from a named journalist's actual operation, but the sample is limited.[R01](https://zhidx.com/p/581004.html)
2. **A non-engineering office team**: A manager asks staff to download it → the department deploys internal Skills for requirements, product, and testing → employees use report/PPT tasks. One user finds it too slow; another replies that it is useful for office work. This is evidence of organizational rollout, but the company is unnamed and there is no sustained deployment data.[R03](https://linux.do/t/topic/2589796)
3. **Team project handoff**: An administrator configures project standards and tools → member A generates analytical material → hands deliverables, a progress summary, assignee, and deadline to member B → B continues within that context. This is a documented collaboration mechanism, rather than ordinary sharing of a chat link.[S19](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Project)
4. **Plaud meeting follow-through**: A recording device captures audio → Plaud transcribes/summarizes and synchronizes to the cloud → an authorized WorkBuddy connector retrieves it → creates a weekly report/customer proposal/follow-up email draft → a person checks before sending. MCP reads existing outputs; it does not start recording or retranscribe audio.[H03](https://www.ithome.com/0/997/585.htm), [H04](https://support.plaud.ai/hc/en-us/articles/57751078986265-Plaud-MCP)
5. **A small merchant's lightweight app**: Describe course booking, student login, and capacity storage → generate an app with a backend → enable cloud services → preview → publish → manually update the live version after subsequent changes. The official tutorial documents a usable product chain; this study found no independent merchant case with ongoing operating bills or retention data.[S12](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/App-Publishing/Web-App)

### At Least Three Distinct Integration Routes

- **Computer audio + shortcut peripherals**: AU05-X and LARK A2. They reduce the effort of launching, dictating, sending, and switching tasks; execution remains in WorkBuddy. They are not standalone computing/offline agents.
- **Existing vertical app + MCP/embedded agent**: Plaud. Hardware captures first, the app transcribes first, and WorkBuddy then handles downstream work. This route most clearly explains “what happens after recording.”
- **Dedicated agent terminals / audiovisual entry points**: Anker desktop companion, Rokid glasses, and other launch-event terminals. Their value is on-site input, status, and confirmation, but public evidence for a complete consumer-ready chain is substantially thinner than for the first two categories.

The hardware list is not nine independent user success stories; nine devices also do not mean nine different agent intelligences.

### What the Feedback Reasonably Supports

- **Established positive product points**: A named article's hands-on work supports in-place co-editing; lightweight forum users in September appreciate simple tasks and lack of configuration; some cross-device users appreciate seeing and replying to computer tasks.[R01](https://zhidx.com/p/581004.html), [R04](https://linux.do/t/topic/2838397), [R12](https://linux.do/t/topic/2722657?tl=en)
- **Specific pain point 1: Mismatched task size.** Sending a small edit through a complex agent chain may cost more waiting/explanation than doing it manually. This appears in both July and September accounts and cannot all be attributed to model knowledge.
- **Specific pain point 2: Long-workflow reliability.** There are historical interruption reports involving expert teams, custom models, long conversations, and authorization/connection recovery. Corresponding fixes do appear in the official changelog, but a fix announcement does not prove every real-world issue has disappeared.
- **Specific pain point 3: Runtime visibility and startup overhead.** A sense that it is “stuck/still processing/returning nothing” affects trust in delivery. This combines UI, runtime, and environment issues. Forum theories involving disk scanning, antivirus, or prompts remain unproven.
- **Evidence still insufficient**: Several weeks of business success rates for ordinary finance/HR/sales users, actual costs after payment, post-purchase hardware retention, and permissions/collaboration incidents as teams scale. A remark such as “one day's work reduced to an hour” cannot become a quantitative conclusion.

## 8. Assessments Ready for Competitive Comparison

1. **Strong breadth**: Documents/data/design/app development, team projects, connectors, and Chinese office services in one product make it a more complete workbench than “universal Q&A.”
2. **Context is already productized**: Project-asset RAG, personal memory, task handoffs, references, shared libraries, and in-place editing all exist. Competitors cannot establish a new category merely by promising to avoid copy-and-paste.
3. **Uneven hardware-integration maturity**: AU05-X and LARK A2 control mappings and Plaud MCP have actionable documentation; some of the nine co-branded devices have reached only display/collaboration-announcement status. Label these separately as “documented and operable,” “vendor says live,” “reporter demonstrated a short chain,” or “awaiting version/unknown.”
4. **Clear usage friction**: Startup/long-conversation/long-task stability, model/tool-configuration boundaries, and orchestration delays for small tasks are more testable pain points than the abstract claim that “AI is not smart enough.”
5. **Insufficient naturalistic validation**: Public material is dominated by launch-period media, training, and tip promotion, with little longitudinal evidence from ordinary business users. This is a research limitation, not grounds to infer either “nobody uses it” or “it must be reliable.”

## 10. Checklist for Hands-On Verification

The full-product review of public evidence is complete, but “comprehensive research” must not masquerade as hands-on testing that was never done. Priority gaps: ① the current personal edition's local/cloud feature matrix; ② concurrent human/AI editing and undo in the same complex Office file; ③ 8-hour tasks, screen lock, and reconnection recovery; ④ exact SKUs, firmware, regions, inventory, and subscription dependencies for all nine devices; ⑤ replayable tasks using real materials from ordinary HR/finance/sales users. Each test should retain version, model, original input, execution record, output, elapsed time, and human corrections to support fair cross-product comparisons.
