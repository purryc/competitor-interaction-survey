Kimi：Agent、Work、Code与Claw

云端研究与办公产物、本地工作空间、编码和持续任务分层；真实PDF/并行任务体验与访问限制并列。

软件能力与版本具体任务怎么做相关硬件与边界实测与用户反馈

核查日：2026-10-06。以下区分官方文档、实际评测和个人自述；未进行统一实机复测。

产品分层

  • Kimi聊天：问答/上传材料/搜索与推理。
  • 云端Agent：自主研究、Office与网站交付，可后台异步，不应因页面没变化就点停止。
  • Agent Swarm：复杂并行/多产物；不把模型参数数目当工作质量。
  • Kimi Work：Windows和Mac Apple芯片本地助手，挂载目录、浏览器扩展、Python/Shell、定时任务，预接部分金融数据。
  • Kimi Code：CLI/编辑器编码产品；API、Code、消费App收费和上限不可互换。
  • Kimi Claw：单独自动化形态，官方帮助指向本地/内网连接；具体部署与配额需按该产品验证。M1、M2、M3

五个完整流程

  1. PDF交叉核查（媒体亲测）：TechRadar 2026-07-10把两份长PDF放同一会话→对照指定章节→追加追问，作者评价结构和准确性较好。仅此任务证据。M4
  2. 竞争研究多任务（同一亲测）：Swarm并行研究→汇合结果→人工检查，作者发现部分子任务不完整且未显著标记。交付审计比并发数更重要。M4
  3. 可执行网站（官方）：目标/素材→Agent生成前后端与存储→预览→发布→下载文件；官方明确未运行可能是沙盒、数据库、认证或未发布。云Agent不能直接读本地文件。M2
  4. 本地季度报告（Work官方例子）：指定目录→搜PDF→汇总为文档并保留来源目录→用户授权后修改/运行。不是上传单一文件的旧聊天形态。M3
  5. 持续工作（Work官方）：设置每日简报/数据脚本→Cron后台运行→结果回到工作空间；官方建议开启保持电脑唤醒，不能宣传电脑关机仍会本地执行。M3

体验、时间与付费

官方说Agent常见任务约5–20分钟，复杂Swarm更久；建议复杂任务拆阶段，承认多轮修改可能遗忘早期细节，普通Agent与多产物模式有差异。文档把上下文写成“256K字符”且给出不一致换算，报告不自行修成精确token指标。M2 TechRadar7月27日作者下载iPhone App却排队无法用，体现可访问性障碍；不能将这一失败套为长期全量不可用。M5 官方套餐动态变化，本轮不以媒体API单价代替App订阅价。未核实Kimi自有硬件。
