Sources checked: 6 October 2026. Official documentation, hands-on reports and personal accounts are distinguished; no standardized device retest was performed.

## Three Different Products
The consumer AutoGLM App's current China store version is 2.0.20 (July 9), requiring iOS 15+. The official description still specifies cloud phones/cloud computers, with tasks running in the background without occupying the local device's interface; this update adds a mobile entry point for AutoClaw. A free store listing does not mean all models/APIs are free. The complete application allowlist and available places were not verified.[G8](https://apps.apple.com/cn/app/id6748391183)
Open-AutoGLM is a separate open-source research framework: an agent runs on a computer and controls existing devices through ADB/HDC and a vision model; WDA configuration documentation is available for iOS. It requires debugging configuration and is emphatically not the same consumer experience as downloading an App and using it immediately. The official repository includes confirmation for sensitive actions and manual takeover for login verification codes.[G1](https://github.com/zai-org/Open-AutoGLM), [G2](https://autoglm.zhipuai.cn/)
Zhipu AI Input Method (智谱AI输入法) has a separate Windows/macOS product page. It addresses cross-app voice writing and does not mean AutoGLM as a whole is merely an input tool.[G3](https://autoglm.zhipuai.cn/autotyper/)

## Actual Workflows
1. **Ordering a drink in the cloud (reporter's hands-on test, 2025-12-10)**: Search Meituan for chilled tofu pudding → filter results/close pop-ups → stop before checkout. The reporter recorded about one and a half minutes. This consumer workflow does not demonstrate completed automatic payment.[G4](https://finance.eastmoney.com/a/202512103587526022.html)
2. **Cloud-phone login (August 2025 review)**: Search for a product → login is required → the user takes over → QR-code scanning/face recognition becomes an obstacle. Different articles conflict on whether login status is retained. This should be retested; do not describe “mandatory login every time” as the current state.[G5](https://www.neican.ai/insights/autoglm-20agent-20250821151004768-0/), [G6](https://developer.cloud.tencent.com/article/2564715?from=15425&frompage=seopage)
3. **Background execution (creator demonstration)**: On 2025-08-22, 卡尔的AI沃茨 demonstrated cloud phones/computers handling tasks while the local device remained usable. The video title and description establish only the demonstration's subject; without watching it, task timestamps must not be invented.[G7](https://www.bilibili.com/video/BV1NretzZEJo/)
4. **DIY with an existing phone (official open-source route)**: Enable debugging and connect → configure the model → provide a natural-language goal → loop through screenshot recognition/tapping/typing → handle sensitive steps manually. This route suits developers and is not equivalent to a zero-setup experience for ordinary users.[G1](https://github.com/zai-org/Open-AutoGLM)

## Feedback from Real Users (Newly Added)
Store reviewer XFTony (February 19) liked the initial experience but wanted iPad support and improvements to authentication takeover. “某位不願透露姓名的劉先生” (August 19) said the phone agent repeatedly disconnected. On 2025-12-20, “懒昀” said they relied on VoiceOver, that the takeover interface was unusable, and that enabling VoiceOver caused crashes. This is an important individual accessibility failure: “the agent can operate the interface” does not mean the user can complete a takeover. Another review dated 2025-08-22 adds that automatic verification-code entry caused a login loop, which was resolved by entering the code manually.[G8](https://apps.apple.com/cn/app/id6748391183)

## Hardware and Risks
There is no evidence that an “AutoGLM phone” is a separate consumer hardware model; a cloud phone is a virtual environment. The open-source version relies on the user's own phone, computer, and model API/local-model resources. Login security, privacy authorization, third-party App risk controls, and the accumulation of errors across steps are the main frictions in deployment.
